Three design decisions in symo

#implementation

Three decisions are worth pulling out of the source.

Float32 tensors, float64 factorizations. Parameters, factors, blocks and the runtime solves are float32; only the compile-time Cholesky and the host-side estimator eigendecompositions run in float64. The heavy data stays in the dtype the hardware likes, and the places where a small matrix can be ill-conditioned get the extra precision. This is the split behind the precision claims: the small dense checks can run in float64 while the large tensors stay in float32 (the round trip).

No global RNG. Everything that draws takes an explicit Nx.Rng.t, so tests and runs replay exactly; the optimizer step itself is deterministic. That is what makes test_jit's parity check meaningful, and it is a good discipline for a library whose correctness claims are numerical (the test suite).

The library contains no model definitions. Models live in downstream code or examples (examples/student_teacher.ml, examples/rnn.ml); only generic parameter-tree machinery is in the library. The consequence is that the symmetry declaration is the user's job (declaring symmetries), and the library never has to guess an architecture.

A fourth decision, recorded in the module docs, is the stable-range check: the compiler raises Invalid_argument below rather than returning a degenerate decomposition (the stable range).
