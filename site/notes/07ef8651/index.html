The symo compiler and orbit architecture — trailhead

#meta#implementation

symo (murder/packages/symo) is the OCaml implementation of the commutant compiler, orbit projections and , Wedderburn block dictionary, and width transport on top of the Raven stack (nx tensors, rune for autodiff and JIT compilation, and ppx_ptree for parameter trees).

Every algebraic object in the vault corresponds directly to an OCaml module in murder/packages/symo/lib/. Compile-time operations (enumerating partial-partition diagrams, evaluating the symbolic Gram matrix on the partition lattice, Cholesky factorization, and constructing the canonical test-vector pairing table and its pseudoinverse ) execute once when the functor Symo.Orbit.Make (M) is instantiated. All runtime operations (estimate_factors, apply_block, to_blocks, of_blocks, transport) are pure compositions of Nx tensor primitives (einsum, reshape, broadcast_to, solve_triangular) with static shapes and no host value reads, so they trace under Rune.jit without retracing.

Notes in this trail

  • Declarative symmetry specifications on parameter trees — how a model declares its parameter tree ([@@deriving ptree]), dimensions, and per-axis Symmetry.spec (Id, Perm i, Absent), and how Symo.Orbit.Make compiles First_order and Second_order.
  • Compiling diagram terms into einsum contractions and Kronecker ties — how Term.coefficient and Compiler.compile_apply_term translate partial partitions (Term.t) into split einsum strings and pairwise 2D identity broadcasts (tie_left_axes) in time and memory.
  • Module correspondence and algebraic verification in symo — the exact mapping between mathematical concepts and library modules (Sides/Index, Symmetry, Term, Component, Basis, Compiler, Kind, Blocks, Orbit), together with the algebraic invariants checked by the test suite.
