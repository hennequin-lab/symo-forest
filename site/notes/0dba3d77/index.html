Everything that wants a matrix

#curvature

Almost every downstream use of a curvature wants the same object: a symmetric positive-definite operator you can store, invert and take functions of.

  • A Laplace approximation of the posterior over weights needs the curvature to build the Gaussian: the posterior precision is curvature plus prior precision, so the requirement is a you can add to and invert.
  • Pruning scores and optimal-brain-damage updates need per-weight curvature. The diagonal, which is what most of them use, is available from the factors without forming the matrix.
  • Continual-learning penalties need a curvature you can afford to store once per task.
  • Influence functions and training-data attribution need .

The paper lists these as future work, and the author has not run any of them, so read the list as a description of the object rather than as results. Each problem already has approximations that make it tractable — diagonal and KFAC-style Laplace approximations, diagonal Fisher penalties, and so on. What is missing in every case is a curvature you can invert and take functions of without diagonalising something the size of the model.

That is exactly what the algebra of the algebra trail and the probe construction of the scale trail provide: an operator stored in numbers (the bill), whose inverse square root is computed on small blocks (the round trip), and which can be transported between sizes (transport). The optimization use is the last section of the source essay, not the first; see the preconditioned step and the durable part.
