# Multi-leaf parameter trees and recurrent mosaics — trailhead

In a feedforward network where each hidden layer has its own independent permutation group, a group id is shared only between the outgoing axis of layer $l$ and the incoming axis of layer $l + 1$. In a recurrent architecture, by contrast, the recurrent state vector $bold(z)_t in RR^(n_z)$ is updated and read out at every time step. A permutation $bold(z)_t mapsto bold(Q) bold(z)_t$ ($bold(Q) in cal(S)_(n_z)$) therefore acts simultaneously on every parameter tensor that touches the state — across both sides of square transition matrices, input projections, biases, and readouts.

When the second-order orbit average $bold(S) = cal(R)_2(bold(u), bold(v))$ is formed over the entire parameter tree $W = ⊕_(i=1)^L W_i$, it partitions into an $L times L$ grid of blocks $bold(S)_(i j) = cal(R)_2(bold(u)_i, bold(v)_j) in cal(C)(W_j, W_i)$ — a **mosaic** of diagonal and cross-leaf intertwiners.
