# Compiling diagram terms into einsum contractions and Kronecker ties

Each [[a0bb3d95|diagram term]] $bold(T)_P$ (`Term.t`) on a leaf pair $(W_R, W_L)$ represents a sparse binary tensor of shape $op("dims")_L "@" op("dims")_R$ scaled by $alpha_P$, paired with a free-axis factor tensor $bold(C)_P$ of shape $f_L times f_R$. Materializing $bold(T)_P$ as a dense tensor would require $O(n^(k_L + k_R))$ memory. Instead, `Term.coefficient` and `Compiler.compile_apply_term` compile each term $bold(T)_P$ into two $O(D)$ closures over `Nx.einsum` and broadcasts.

## 1. Factor projection closure (`Term.coefficient`)

To project an outer product $bold(X) = bold(u) bold(v)^top$ ($bold(u) in W_L, bold(v) in W_R$) onto $bold(T)_P$ in [[e176661b|the normal equations]], we need the free-axis tensor
```typst
(bold(B)_P)_(alpha beta) = alpha_P sum_(bold(i), bold(j)) lr((product_(B in P) delta_B (bold(i), bold(j)))) u_(bold(i), alpha) v_(bold(j), beta).
```
`Term.coefficient` compiles this sum into an einsum pattern string at compile time:
1. Assign a distinct character label (`Index.to_char`) to each axis of $bold(u)$ (`Left 0`, `Left 1`, $dots$) and each axis of $bold(v)$ (`Right 0`, `Right 1`, $dots$).
2. For each tie block $B in P$, pick the first axis in $B$ as its representative and overwrite the character label of every other axis in $B$ with the representative's character. In einsum notation, repeating a character across or within operands restricts the sum to the diagonal where all those indices are equal — implementing $delta_B(bold(i), bold(j))$ with zero extra memory.
3. Place only the character labels of the free axes $P."free"$ into the right-hand output string `out_eq`. All permuted axes (both tied representatives and untied singletons) are omitted from `out_eq` and therefore summed out by `Nx.einsum`.
4. For `` `Outer_product (u, v) ``, the two-operand pattern `in_left ^ "," ^ in_right ^ "->" ^ out_eq` contracts $bold(u)$ and $bold(v)$ directly without forming $bold(u) bold(v)^top$, and multiplies the result by the scalar normalizer $alpha_P$.

## 2. Operator application closure (`Compiler.compile_apply_term`)

Given a factor tensor $bold(C)_P$ of shape $f_L times f_R$ and a batch of right-hand vectors $bold(v)$ of shape $"batch" times op("dims")_R$, `compile_apply_term` computes the batch of left-hand outputs $bold(w) = (bold(T)_P ⊗ bold(C)_P) bold(v)$ of shape $"batch" times op("dims")_L$:
```typst
w_(z, bold(i), alpha) = alpha_P sum_(bold(j), beta) lr((product_(B in P) delta_B (bold(i), bold(j)))) (bold(C)_P)_(alpha beta) v_(z, bold(j), beta).
```
A tie block $B in P$ can involve right axes, left axes, or both. `compile_apply_term` classifies each block $B = B_L union B_R$ into three mechanisms:

1. **Right-side ties ($|B_R| >= 2$):** All right axes in $B_R$ are assigned the character label of their representative $r_"rep" in B_R$ in the input string `v_eq`, so `Nx.einsum` extracts the diagonal along $B_R$ in $bold(v)$.
2. **Left–right cross ties ($B_L != emptyset$ and $B_R != emptyset$):** The first left axis $l_"rep" in B_L$ is assigned the character label of the right representative $r_"rep" in B_R$ in the output string `out_eq`, routing the uncontracted right index directly to the left output position $l_"rep"$ without summing over $r_"rep"$.
3. **Left-only ties ($|B_L| >= 2$) and untied left axes:** Standard einsum notation cannot create a diagonal on *output* axes that do not appear in the input operands (or duplicate an output label). Therefore:
   - Untied left permuted axes ($l in.not op("inv")(P)$) and secondary members of left ties ($B_L backslash {l_"rep"}$) are omitted from `out_eq` and initially reshaped to singleton dimensions of size $1$.
   - For each left tie block with $|B_L| >= 2$, `Compiler.tie_left_axes` enforces equality across $B_L = {l_1, l_2, dots, l_r}$ by multiplying the tensor pairwise by reshaped 2D identity matrices $bold(I)_n$ along axes $(l_1, l_2)$, then $(l_2, l_3)$, and so on. Applying 2D identity matrices two axes at a time avoids ever materializing an $r$-dimensional delta tensor of size $n^r$.
   - Finally, `Nx.broadcast_to` broadcasts any remaining singleton dimensions (untied left axes, where $bold(T)_P$ is constant $1$) to the full output shape $"batch" times op("dims")_L$.

Because every step is a fixed-shape `einsum`, `reshape`, elementwise multiply by $bold(I)_n$, or `broadcast_to`, the compiled closure traces into a static computation graph under `Rune.jit`.
